# PP-Tracking 多算法演进设计

日期：2026-09-19。分层：单 SDK；门户仅记录路线和已发布版本。
用户已确认在同一个 Tracking SDK 中逐步接入七种方案，先推进 OC-SORT，再评估外观辅助和模型驱动方案。

## 目标与边界

2026-09-21 最新状态：三算法 `0.2.0-rc.0` 已发布 npm `next`、线上 Demo 与 OIDC 回读通过，`latest` 保留 `0.1.0`，见[发布回执](../../../reports/tracking/2026-09-21-02-release/README.md)。随后[BoT-SORT 可行性](../../../reports/tracking/2026-09-21-botsort-feasibility/README.md)完成：固定七段 5316 帧/67639 检测，原 ByteTrack、加 CMC、再加门控外观融合的 IDF1 为 48.2922%/54.5850%/55.3487%，IDSW 为 1101/519/489。09 段退步，离线图像估计逐段中位数约 34–48 ms，未在浏览器实现。优先进入**外部帧间矩阵输入的同包 CPU 核心设计与实现**，可选浏览器估计器后置；这次探针保留原滤波/生命周期且有论文差异，不能称为完整 BoT-SORT 或第四算法已发布。ByteTrack 继续默认，视频/摄像头与 Workflow 仍待独立设计；以下阶段记录保留历史时点。

`web-sdk-pp-tracking` 按跟踪任务组织，不按算法拆成七个 npm 包。最终目标覆盖 ByteTrack、OC-SORT、DeepSORT、BoT-SORT、JDE、FairMOT、CenterTrack；这是接入目标，不代表全部已兼容。每项独立核验来源/许可、必要权重、数值、生命周期、浏览器、分发，未通过者保留候选及阻塞原因。

| 路线 | 输入与依赖 | 接入顺序与当前状态 |
| --- | --- | --- |
| ByteTrack 思路独立实现 | 检测框、分数、类别、时间戳 | 稳定 0.1.0 与 RC 0.2.0-rc.0 的默认；历史基线及本轮恒等补偿输出一致，具体质量范围见固定证据 |

| BoT-SORT | 检测框、运动补偿，按配置加 ReID | 2026-09-21 完成本地 CMC/外观融合探针，有合计收益与局部退步。下一批先设计外部矩阵 CPU 核心；自动浏览器估计、生产输入契约与公开算法入口尚未实现 |

| FairMOT | 图像经联合网络产生框和外观特征 | 在 JDE 可行性之后评估；权重、许可和输出数值边界尚未核验 |
| CenterTrack | 当前/历史帧和历史目标信息，时序模型 | 在图像时序输入准备后评估；历史帧调度、模型权重和浏览器适配尚未实现 |

三类能力分别为框输入、框加外观特征、图像输入，共享可解释的轨迹输出和 reset/dispose 语义。涉及模型的路线将按需加载权重，模型来源继续默认 ModelScope、提供 Hugging Face；不使框输入调用者下载未用模型。
标准 1.2.0 已允许算法工厂和领域输入输出，同一纯算法 SDK 的多个策略可沿用当前 manifest。标准 1.3.0 已本地实施算法/模型混合声明；正式接入仍须满足模型的权重、缓存、分发和 Demo 要求，不能借 `kind: algorithm` 豁免。

视频和摄像头仍是重要体验目标：宿主负责媒体与帧调度，检测器提供框，跟踪器关联轨迹。七种算法切换本身不会自动产生检测框。视频联调示例、外观模型适配和本轮框输入核心分别验收，门户 Workflow 暂缓，3D 调研后移。

## 下一批：外部运动矩阵核心

研究结论推荐同包可选 BoT-SORT 风格策略；先完成正式设计，暂不把一次性探针代码提升为生产实现。矩阵必须描述上一成功处理帧到当前帧的原图坐标变换，并携带 from/to 帧和时间身份；区分估计成功、明确恒等和失败/不可用，规定丢帧组合、首帧、seek/reset、尺寸变化与错误不推进。关联中的补偿顺序、框包络与协方差变换、可选外观门控均需明确论文差异和反例。

验收包括旧三算法回归、矩阵/向量/框输入的错误原子性、Node/浏览器同输入质量、09 退步调查及估计/关联分层成本。可选图像估计子入口须单独核对浏览器依赖许可、性能与失败行为；检测、ReID、估计和媒体编排由明确宿主契约连接，不复制到门户。标准 1.3.0 的领域输入及可选模块可承载该设计，本研究阶段不新增标准字段或公开 API 承诺。

## 第一批接口

`createTracker(options)` 增加 `algorithm?: 'bytetrack' | 'ocsort'`，缺省为现有 ByteTrack 思路实现。实例算法固定；切换创建新实例，清空历史，不继承轨迹 ID。
`TrackingResult` 增加所用算法标识；返回值增加字段不改变原轨迹/代次/耗时语义。未知算法返回 `INVALID_OPTIONS`，不回退。

已有 ByteTrack 数值与状态转换保持，新增选项与 OC-SORT 私有选项互斥。OC-SORT 沿用高分阈值、建轨阈值、IoU 门限和生命周期参数；不使用 ByteTrack 低分续接，显式传入无效的专属选项应拒绝，Demo 仅显示当前算法有效参数。
OC-SORT 只实现 CPU/main。无权重，不显示 GPU、模型下载或缓存控件。

## OC-SORT 机制与实现边界

基于公开论文描述与现有独立数学内核实现：观测方向关联（OCM）、遮挡重现时观测重更新（ORU）、使用最后真实观测重新匹配（OCR）。禁止读取/翻译旧 SORT、DeepSORT、Paddle/OC-SORT 来源义务未清晰的 Kalman 或跟踪源码。

先固定论文版本/摘要和数学设计，明确角度评分、IoU 硬门限、真实观测历史与虚拟观测的区分。ORU 从最后真实观测后的滤波快照恢复，按缺失更新时刻插值重放，再校正当前真实观测。历史和重放必须有界；超过公开上限的轨迹按明确策略结束，不执行无界循环。具体参数边界与公式在 SDK 算法指南记录。

复用本项目 8 维位置/尺寸/速度滤波、秒级时间戳、严格类别隔离和生命周期。这些是独立实现选择，不能宣称与官方七维/帧间隔实现逐值兼容。方向评分不绕过原始 IoU 或类别门限。成功计算后才提交全部运动状态、观测历史、时间、ID；异常或预取消保持状态不变。

## Demo 和文档

沿用现有紧凑工作台，增加算法选项。选项仅列实际实现并完成本地验收的策略，不把未来路线显示为可用。切换后停止播放、重置帧和轨迹，语言切换仍保留状态；导出包含算法、有效配置与原始时间。
中文/英文指南说明各策略、专属参数、已知差异、真实评测与输入限制。本地候选标为 `0.2.0-alpha.0`，线上仍是 `0.1.0`，门户生产条目不提前更新。

## 设计进度（2026-09-19）

第一批的接口、OC-SORT 独立数学实现、Demo 策略切换、双语文档、本地候选版本及两算法同输入评测已完成；Demo 只显示 ByteTrack 与 OC-SORT，切换停止播放并从有效配置重建，导出携带实际算法和已应用选项。候选报告位于 SDK 的 `reports/2026-09-19-ocsort/README.md`：固定七段训练序列的结果支持继续保留 ByteTrack 默认，不把 OC-SORT 描述为整体更优。当前剩余的是候选独立发布判断，以及第二批外观/图像输入的来源与契约可行性。门户生产 registry、运行时代码和 0.1.0 条目在本批次不变。

第二批可行性（2026-09-19）：[阶段回执](../../../reports/tracking/2026-09-19-reid-feasibility/README.md)记录来源和实测。Intel OMZ 0288 FP32 是许可明确的技术探针，不是 Paddle 权重；转换后约 1 MB，Python 八组对齐通过，浏览器 WASM/WebGPU 各六组通过、全黑和全白失败，因此不选入发布清单。Paddle PPLCNet 保留下一模型候选，尚未转换。建议先设计并实现 CPU/main 的外部外观向量 DeepSORT 策略，固定特征空间身份、严格向量验证、归一化与有界图库；模型/裁剪/媒体另行验收。纯外部向量策略仍可用算法标准 1.2.0，同包提供模型加载前须先扩展混合能力标准。此分阶段安排与原设计一致；目前没有新增第三种算法、模型或 GPU 产品声明。

第二批外部向量实现采用[专门设计](2026-09-19-pp-tracking-deepsort-design.md)和[实施计划](../plans/2026-09-19-pp-tracking-deepsort.md)：固定 featureSpace 身份与维度，严格校验每条向量，采用有限图库、四维运动门控、外观匹配级联和有限 IoU 后备。[本地阶段验收](../../../reports/tracking/2026-09-19-deepsort/README.md)已完成：完整 verify 102项单测与三算法包消费通过，后续修复的14项Demo聚焦和12组浏览器检查通过，最终独立复审可本地交付。修复了样例切换误用草稿和高维输入导出超过5MiB的边界，输入序列与结果报告分开导出。此阶段仍无内置 ReID 模型，不改变 ByteTrack 默认，也不扩展真实质量和后端承诺。下一步核验PPLCNet ReID具体权重、预处理和真实图像质量。

第二批 PPLCNet 模型研究（2026-09-19）：[本地评测回执](../../../reports/tracking/2026-09-19-pplcnet-reid/README.md)记录具体权重、33,704,835字节 FP32 ONNX 和32组 Paddle/Python/WASM/WebGPU数值验证。两个官方权重 URL 内容一致；模型结构和读取的预处理文件为 Apache-2.0，checkpoint独立模型卡/完整训练数据条款尚未补齐。MOT17两个序列120个真实裁剪、25个图库身份、95次同摄像头查询中，正常RGB第一名正确87次，上游转置BGR为75次；发现上游裁剪轴/通道差异，不能直接照搬或视为真实MOT指标提升。下一步冻结图像预处理契约、用独立样本检查通道与阈值并补齐分发说明，再演进混合标准及同包可选ReID加载；真实检测同输入的跟踪对比随后进行。SDK仍为三算法CPU/main产品，GPU只在研究探针中测得；门户仅记录路线，Workflow继续暂缓。

第二批图像输入研究（2026-09-20）：[阶段回执](../../../reports/tracking/2026-09-20-reid-preprocessing/README.md)记录预处理候选、34组Node/Python/Chromium张量一致及WASM/WebGPU特征通过。独立五段MOT17训练序列103裁剪、67查询中，确定性RGB正确53/67，支持继续采用正常朝向RGB；未调优0.2距离门限，不等于真实跟踪精度提升。33组不透明PNG解码一致，透明PNG反例有7/16字节变化，因此下一模型入口只接受已解码RGBA，不声称任意文件解码保真。双语模型卡说明来源与许可证据范围；[混合标准提案](../../../standards/v1/proposals/algorithm-model-hybrid.md)和[模块设计](2026-09-20-tracking-reid-module-design.md)已形成，标准仍1.2.0，生产接入前须先实施。后续顺序为标准、可选子入口、本地模型字节闭环、真实分发/Demo及真实检测同输入评测；门户生产条目和Workflow边界保持原规划。

## 第一批验收

第二批公开入口与分发（2026-09-21）：[阶段回执](../../../reports/tracking/2026-09-21-reid-distribution/README.md)记录固定33,704,835字节模型在ModelScope/Hugging Face的真实不可变revision、匿名下载与SHA。采用官方仓库整体Apache-2.0作为官方链接checkpoint转换分发依据，并保留独立声明与训练披露缺口。根入口不加载ORT，可选./reid在load才加载引擎；本地Demo可输入图像与人体框进行单帧提取并交给DeepSORT，模型CPU/GPU和关联CPU分别展示。四组真实来源数值、生产模型工作台与390px中英文均已本机验证；人工图与重复帧不证明MOT提升。下一阶段用相同检测输入比较ByteTrack、OC-SORT、DeepSORT的真实时间序列质量和完整成本，再决定0.2版本发布。视频/摄像头调度及其余四算法继续后置；门户Workflow不提前实施。

第二批模块实现（2026-09-21）：[本地阶段回执](../../../reports/tracking/2026-09-21-reid-module/README.md)记录标准 1.3.0 与同包 `src/reid/` 候选。RGBA 和人体框可提取 512 维外观向量供 DeepSORT 使用，WASM/WebGPU 各 34 组对 Paddle 参考通过，取消恢复及真实浏览器缓存验证通过。根包保留算法入口，不包含 ORT 或模型；正式双源尚未落实，因此候选只构建到忽略目录，公开子入口、hybrid 生产清单和 Demo 一起留待分发阶段。重复帧只验证接口，不代表真实跟踪质量；后续继续补齐真实来源与同检测输入评测。

- 基线 50 项测试已通过；新增机制测试先失败后实现，覆盖方向歧义、零位移、硬门限、遮挡重现、观测重更新、历史上限、错误原子性、重置和释放。
- 现有 ByteTrack 默认轨迹输出与原有固定 MOT17 评测保持一致（算法/版本元数据及耗时除外）。
- 两算法使用相同 MOT17 七段 FRCNN 训练序列 5316 帧与固定 TrackEval，各运行并重复核验确定性，记录 IDF1/IDSW/MOTA/FP/FN、容量和耗时；不预设 OC-SORT 必须更优。
- Chromium 至少一完整真实序列对齐 Node 的非耗时结果，覆盖两算法；Demo 算法选择、语言、导入导出、播放、seek、参数和 390px 验证通过。
- SDK 修改前后 checker、完整 verify、实际 ESM/CJS 打包消费与相关门户文档检查通过，独立审查无阻塞问题。
- 本批次本地实现与评测，不进行新一轮 GitHub/npm/模型仓库远程写操作。发布作为达到门槛后的独立阶段。

## 方案取舍

采用同包策略选择及按阶段增加输入能力。按算法拆包会重复公共生命周期和文档；直接塞入所有模型会提前引入未经验证的输入和权重要求。当前选择先完成两个同输入策略，再以实际外观/时序模型的契约演进，保持旧 API 可用。

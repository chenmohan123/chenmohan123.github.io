# PP-Detection 下载恢复与三精度接入实施计划

> 执行方式：使用 superpowers:subagent-driven-development 分配独立任务，主执行者负责集成及最终审查。用户已确认前两项维护方向，常规实现选择连续推进。

目标：让现有模型下载遇到无响应、持续过慢和短暂网络故障时能够有界恢复，同时使 SDK 指南与门户准确呈现两模型六个稳定变体。

范围：单 SDK runtime 和文档，以及门户登记数据。SDK 基线 `2bf1bc2`，门户基线 `e30f186`。现有干净检出使用独立功能分支；保持已发布 SDK 0.3.1 的模型兼容性记录，新增下载行为记录为未发布维护改动。小目标检测属于后续阶段。

## 已确认行为与实施决定

- 在现有权重下载入口增加可选 `download: { timeoutMs, idleTimeoutMs, maxRetries }`，通过 `createPPDetection`、`ModelManager` 到 `loadModelAsset` 传递同一策略。
- 默认每次请求总时限180秒、无新增字节时限30秒、最多重试2次（共3次请求）。总时限用于处理持续少量进度的慢连接；两个时限可分别设置为0关闭，重试次数可为0。参数须为安全整数，时间不超过浏览器计时器范围，重试次数0至5。
- 第一次重试等待500毫秒，第二次1000毫秒；后续自定义重试延迟至多4000毫秒。等待期间可取消。每次请求保持相同不可变来源URL，重试可用fetch的reload缓存模式重新建立连接。
- 只重试请求/响应流网络故障、内部超时和HTTP 408/429/500/502/503/504。取消、完整性校验失败、错误206范围及其他HTTP错误不重试。
- 超时/取消主动中止当前请求并取消响应流；即使自定义fetcher或流不响应AbortSignal，调用方也应及时收到错误，迟到的旧响应不能污染进度或缓存。
- 重试重新下载完整文件，不拼接不完整字节。每次从0开始报告进度，追加可选attempt/maxAttempts信息，最终只缓存通过字节数和SHA-256验证的完整模型。下载耗时覆盖重试与等待。
- 本轮不改模型清单协议；下载参数是SDK的可选调用配置，已有调用保持兼容。清单JSON加载仍遵循既有流程，新增策略明确用于ONNX权重。

```ts
const detector = await createPPDetection({
  model: immutableManifestUrl,
  source: "modelscope",
  precision: "int8",
  download: { timeoutMs: 180_000, idleTimeoutMs: 30_000, maxRetries: 2 }
});
```

# Tracking BoT-SORT 可行性回执（2026-09-21）

分层：独立 Tracking SDK 的研究评估，门户只同步结论与路线。

已在固定 MOT17 七段 FRCNN 训练序列全部 5316 帧、67639 检测上比较原 ByteTrack、相同内核加相机运动补偿（CMC）、再加门控外观融合。协议预先固定，GT 仅独立评分进程读取；沿用旧 PPLCNet 冻结向量，本轮未新增模型或重测 ReID 推理。

CMC 合计 IDF1 提高 6.2928 个百分点；外观融合再加 0.7637 个百分点。但 MOT17-09 的 IDF1 为 48.7551% → 45.2744% → 46.5909%，两配置都退步；05/11 的外观融合也有局部退步。只支持继续研究，不支持更换默认或宣称所有场景更优。

估计器是离线 Python/OpenCV ORB + RANSAC，未进入浏览器：单线程、最大宽 640，每段估计中位数约 34.16–47.80 ms，全部估计累计 239.28 秒，包含读取校验/解码缩放共 288.72 秒。5316 帧 Node 跟踪累计约 10.07/10.30/12.99 秒，不含图像估计、ReID、检测器和渲染，不能相加推断不同设备上的实时 FPS。

全七段恒等补偿输出对齐原基线、原 ByteTrack 的 MOT 哈希对齐历史、三配置零容量丢弃。Chromium 153 对完整 MOT17-05 的 837 帧三配置回放，MOT 及所有非耗时输出哈希均与 Node 一致；这仅证明浏览器 CPU 关联与矩阵应用，不证明浏览器图像估计、模型推理、摄像头或手机。

本轮探针采用原 SDK 的滤波噪声和生命周期，加独立推导的轴对齐包络/协方差变换及门控最小距离/EMA；与论文宽高映射、阈值边界等存在明确差异，未完整复现 BoT-SORT。生产包、manifest、模型、算法注册和 Demo 无新接入。SDK 公开状态沿用[上一轮发布回执](../2026-09-21-02-release/README.md)：`next=0.2.0-rc.0`、`latest=0.1.0`。

来源固定到 BoT-SORT `251985436d6712aaf682aaaf5f71edb4987224bd`、论文 `arXiv:2206.14651v2`、PaddleDetection `b25522a0f4bde8c80603f3ba5e3472059972e3b5`。BoT-SORT 根 MIT 不概括 Apache-2.0 的 fast_reid 与 GPL-3.0 的 yolov7；本轮只读论文/README/许可/Paddle配置，未读取或复制第三方跟踪实现。Paddle 配置默认关闭 CMC 和 ReID，使用 MOT17 half 专用检测权重，其成绩不能与本次全 train FRCNN 直接比较。

下一阶段优先**同包接收调用者提供矩阵的 CPU 跟踪核心**。先设计原图仿射方向、from/to 已处理帧与时间戳、identity/失败状态、丢帧/seek/reset/尺寸变化、错误不推进及可选外观契约；再实现 BoT-SORT 风格策略和同输入验证，调查 09 退步。自动图像估计保留可选独立子入口，需新增浏览器成本及依赖许可验收。视频/摄像头编排与门户 Workflow 后置；同任务算法同包的最初规划不变，不要求本轮扩标准 schema。

完整研究文件在 SDK 本地提交 `99928c639d84f30efcd5b4686d9e7144c5b818e5` 的 `reports/2026-09-21-botsort-feasibility/`：双语报告、固定协议、来源锁、数学/集成探针、评分、逐段摘要、浏览器回执、完整性校验及失败日志。原图、GT、公开检测、向量、真实轨迹和论文全文未归档到 Git。研究尚仅本地，因此不提供不存在的远程证据链接。
